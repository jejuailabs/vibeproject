# 수용 기준과 검증 시나리오

아래는 구현 때 검증할 기준이다. 현재 문서 작성만으로 테스트가 실행되었다는 뜻은 아니다.

## 테스트용 인물

A: 기수 1 참가자 / 프로젝트 P1 리더.
B: 기수 1 참가자 / P1 팀원.
C: 기수 1 참가자 / P2 팀원.
D: 기수 1 관리자, P1 팀원 아님.
E: 기수 2 참가자.
F: Google 로그인만 한 미가입자.
자료는 가상 이름과 가상 대화를 사용한다.

## 현장 리허설

가상 활동을 열고 QR로 모바일 참여 → 첫 생각 작성 → 다른 사람의 질문 → 카드 확정 → 투표 → 팀 구성 → 문서 확정 → 데모 공유 → 발표.
운영자 화면에 제출과 도움 요청이 표시되는지 확인한다.
네트워크 단절 시 작성 내용이 즉시 사라지지 않으며 미전송을 성공으로 표시하지 않는다.
프로젝터 모드에 개인 알림이나 팀 대화가 나타나지 않는다.

## 의미 있는 자동화

- 상태 전환과 투표/팀 정책의 단위 테스트.
- Emulator 기반 Rules 및 서비스 권한 통합 테스트.
- 선정/투표/멤버 승인/베이스라인/멱등성 동시성 테스트.
- 핵심 참가자 흐름 E2E, 역할별 접근 E2E.
- AI 출력 스키마와 승인 전 무변경 테스트.
- 내보내기 manifest와 버전 일치 검증.

정적인 라벨/단순 색상 변경에 구현을 그대로 복제하는 테스트를 늘리지 않는다.
UI 색상·여백·오버플로는 실제 화면으로 확인한다.

## 배포 전 수동 확인

Google 로그인/로그아웃, 실제 허용 도메인, 기수 가입, 모바일 작성/채팅, 파일 접근, 알림 직접 링크, 발표 데모.
1440/1024/390px에서 키보드 접근과 읽기 순서, 포커스, 긴 한국어 콘텐츠를 확인한다.

## 릴리스 차단 조건

권한 누출, 데이터 손실, 잘못된 투표/팀 승인, 이력 원본 단절, 핵심 경로의 전송 실패 은폐.
미정 AI 공급자 자체는 수동 경로가 완성되었으면 차단 조건이 아니다.
알려진 문제와 비활성 기능은 릴리스 기록에 명시한다.
