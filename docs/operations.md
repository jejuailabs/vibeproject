# 4주 현장 운영 가이드

주차별 총 수업 시간과 참가 인원은 미정이다. 아래는 시간표가 아닌 운영 순서이며, 일정은 기수 설정에서 입력한다.

## 사전 준비

기수 생성, 운영자/퍼실리테이터 지정, 초대, 일정, 기수 이름, 아바타 기본값, 공개·보관 안내.
전체 채팅과 활동 템플릿 생성.
참가자용 접속/로그인 안내와 현장 QR 준비.
AI 기능을 쓰지 않아도 수동으로 카드를 정리할 수 있는지 확인.

## 1주차 — 경험에서 문제로

1. 운영자가 '불편했던 경험' 활동을 연다.
2. 참가자가 오프라인 대화를 진행하고 첫 생각을 입력한다.
3. 녹취록이 있으면 정리 초안을 만들고 당사자가 확인한다.
4. 공동 보드를 보며 질문과 공감을 남긴다.
5. 문제 대상·상황·불편을 구체화한다.
6. 작성자가 카드 내용을 공유 버전으로 확정한다.

결과: 참가자별 문제 카드, 관련 질문, 최초 버전.
운영자 확인: 미제출자에게 도움, 작성자/발언자 오연결 수정, 원본 공개 범위 확인.
숙제 가능: 다른 카드에 질문 남기기, 자신의 카드 보완.

## 2주차 — 선택·구성·준비

1. 개인/팀/혼합 진행 방식을 정한다.
2. 필요 시 후보 카드와 버전을 고정하고 투표한다.
3. 결과 토론 후 최종 선정과 이유를 남긴다.
4. 미선정 후보는 종료 보관한다.
5. 참여 신청과 구성원 확정으로 프로젝트를 만든다.
6. 개인 환경과 프로젝트 서비스 준비를 나누어 진행한다.
7. 기획 질문을 시작한다.

결과: 프로젝트, 구성원/리더, 출발 아이디어, 준비 상태, 기획 초안.
표가 적은 사람의 문제를 가치 없는 문제로 표현하지 않는다.
개인 진행은 팀에 억지로 배치하지 않고 동일 프로젝트 구조를 사용한다.

## 2~3주차 — 구현 가능한 기획

문제/사용자 → 핵심 흐름 → 기능 범위 → 화면 → 디자인 참고 → 데이터/권한 → 완료 기준.
팀 대화에서 나온 결정은 확인 후 결정 기록으로 전환한다.
기획을 베이스라인으로 확정하고 main.md/docs를 내보낸다.
개발 에이전트 시작 지시문과 문서 묶음을 전달한다.
원문 대화 전체를 개발 에이전트에 반드시 전달할 필요는 없다.

## 3주차 — 개발과 첫 시연

준비 체크 → 개발 → 첫 배포 → 동료 사용 → 피드백 → 수정.
체크인은 '오늘 한 일 / 막힌 점 / 다음 행동'으로 피드에 작성한다.
운영자는 접속 시간을 감시하기보다 도움 요청과 미완료 준비를 본다.
대상/기능 범위가 바뀌면 기획과 이력을 갱신한다.
시연 버전은 어떤 기획 베이스라인을 구현했는지 표시한다.

## 4주차 전반 — 마무리

핵심 흐름 점검, 발표용 배포, 알려진 문제 정리.
프로젝트별 주요 전환점 3개, 최초 생각과 최종 결과, 회고를 작성한다.
공개 타임라인에 팀 내부 대화가 그대로 노출되지 않는지 확인한다.
최종 기능 추가보다 시연 경로의 안정성과 설명을 우선한다.

## 4주차 후반 — 발표·질의응답·교류

발표/질의응답/네트워킹 총 90~120분.
발표 배정 시간 = (전체 시간 - 교류 시간 - 시작/전환/마무리 시간) / 프로젝트 수.
예: 120분 - 교류 30분 - 진행 10분 = 80분. 8개 프로젝트라면 10분씩.
실제 프로젝트 수에 따라 운영자가 시간을 설정한다.

발표 화면: 문제, 데모, 변화 과정, 알려진 제약, 다음 단계.
참가자는 프로젝트별 질문/피드백을 남긴다.
교류 화면은 프로젝트와 관심 주제를 보여주되 개인 연락처를 자동 공개하지 않는다.

## 일상 운영 예외

- 늦은 참가: 초대 후 현재 활동부터 시작, 이전 활동은 읽기와 보완 제출 정책 적용.
- 팀 이동: 담당자 협의, 기록, 권한 회수/부여. 과거 저작자 표시는 유지.
- 리더 부재: 기수 관리자가 이유를 남기고 리더를 이관.
- 투표 동점: 토론/재투표/선정 이유 기록.
- 제출 후 마감: 자동 수정 금지. 운영자가 재개 또는 예외 제출 승인.
- 장애: 오프라인 활동은 계속하고 나중에 입력. 실제 대화 시각과 등록 시각을 구분.
- AI 오류: 수동 수정, 원문 확인, 잘못된 승인 내용은 새 버전으로 정정.
- 부적절한 글: 제한된 신고/검토/숨김 절차.

## 종료와 보관

기수 완료 시 정해진 기간 동안 읽기 중심으로 유지한다.
활동·투표·팀 편집을 잠그되 관리자 정정은 기록한다.
운영 전에 원본 녹취록/메시지/첨부/내보내기/백업 보관 기간을 결정하고 안내한다.
기수 참가자만 보는 전시가 기본이다. 인터넷 공개는 별도 동의와 기능 범위로 취급한다.
개인정보 삭제·정정 요청에는 원본과 파생 요약을 함께 확인한다.

## 운영자가 볼 핵심 현황

현재 활동 제출 수, 준비 항목 미완료 수, 도움 요청, 프로젝트 단계, 마지막 주요 업데이트, 첫 배포 여부, 발표 자료 준비 여부.
참가자 순위나 무근거 역량 평가를 생성하지 않는다.
