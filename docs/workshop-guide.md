# 워크숍 기능 운영 가이드 — 0.3

기준일: 2026-10-17. 앱은 Vercel, 인증·데이터·첨부·캐릭터는 Firebase를 사용한다.

## 1주차: 현장의 생각을 기록하기

1. 관리자/퍼실리테이터가 **워크숍 진행 → 현장 활동 → 새 활동 열기**에서 질문, 안내, 마감을 입력한다.
2. 활동의 **링크·QR 공유**로 참가자가 들어온다. Google 로그인만 하면 참가자로 자동 가입된다.
3. 참가자가 활동 결과를 개인 또는 전체 공개로 제출한다. 수정 전 결과는 이력에 보관한다.
4. 자신의 결과를 아이디어로 연결하고, 아이디어 보드에서 댓글을 나눈다.
5. 생각 카드에서 **이 생각 구체화하기**를 누르고 누가 / 언제·어디서 / 무엇을 하려다 막히는지 / 현재 해결 방법 / 빈도를 적는다. 일부만 임시 저장할 수 있다.
6. **저장하고 문제정의로**를 눌러 문제의 영향·해결 후 변화, 문제정의 문장, 통제범위를 적는다. 앱 이름이나 만들 기능을 미리 넣지 않는다.
7. **함께 보는 생각 보드**에서 처음 생각·경험 구체화·문제정의 초안·선정 준비를 열별로 본다. 각 카드의 **피드백**을 열어 해당 내용에 질문이나 제안을 남긴다. **이 흐름만 보기**로 한 아이디어만 모아 볼 수 있다.
8. 초안 1에 받은 의견을 보고 변경 이유와 함께 초안 2로 다듬은 뒤 **선정 준비 완료**를 누른다. 이전 초안과 피드백은 해당 버전에 남는다. 단계 이름으로 초안만 모아 비교하거나 **이 아이디어의 이전 버전 더 보기**로 과거 기록을 추가한다.
9. **전체 공유 화면**은 전체 공개 결과만 표시하며 개인 제출·팀 대화·알림을 제외한다.

녹취록은 **자료·녹취록**에서 직접 입력하거나 TXT/MD를 가져온다. 원문에 실제로 있는 구간을 근거로 제안하고, 검토 후 아이디어·질문·요약·작업·결정에 반영한다.

## 2주차: 투표와 구성

- 기수 운영에서 개인/팀/선택 방식을 정한다.
- 다섯 질문과 문제정의를 완료하고 기수 전체에 공유한 카드가 새 투표 후보로 표시된다. 투표 시작 시 후보 원본과 revision, 문제정의 초안을 고정한다. 참가자별 예산, 자기 투표 허용, 서버 마감시각을 적용한다.
- 마감 전에는 자기 표만 조회·수정한다. 관리자도 다른 사람의 개별 표를 API로 받지 않는다.
- 관리자가 집계 후 선정 대상과 이유를 확정한다. 선정하지 않은 해당 라운드 후보만 종료한다.
- 팀 참여 신청은 팀장 또는 관리자가 승인한다. 한 사람의 활성 프로젝트는 하나이며 정원 검증은 트랜잭션 안에서 수행한다.
- 개인 방식은 본인이 전체 공유한 아이디어에서 바로 시작한다. 팀장은 이관 후 탈퇴할 수 있다.

## 2~3주차: 기획과 개발

**기획·개발**에서 개인 준비 항목과 팀 준비 항목을 확인한다. 참가자의 외부 계정·프로젝트는 각자가 생성하며 앱에 비밀키를 입력하지 않는다.

첫 `문제와 사용자` 문서를 열면 선정한 카드의 질문 답변·문제정의·통제범위를 시작 내용으로 보여준다. 이미 저장한 문서는 유지한다.

문서 7개: 문제/사용자, 기능, 화면, 디자인, 데이터/권한, 환경/배포, 완료 기준. 모든 저장에는 revision과 이유를 기록한다. 다른 사람이 수정하면 입력을 유지하고 충돌을 알린다.

팀장이 7개 문서 revision을 한 번에 확정하면 불변 버전 묶음이 생성된다. **MD · ZIP 받기**에는 루트 main.md, docs 아래 7개 문서, SHA-256 manifest.json이 포함된다. 복원은 새로운 초안을 만든다. 원문 정정으로 연결 문서가 철회되면 해당 과거 묶음의 신규 내보내기는 중지된다.

개발 준비 → 개발 중 → 시연·검토 → 완료 순서에는 체크리스트, 기준 버전, 배포, 공개 발표의 선행 조건이 있다. 뒤로 이동할 때도 이유가 남는다.

작업 보드, 결정 기록, GitHub/Vercel/Firebase 링크, 배포 버전, 도움 요청을 함께 사용한다.

## 4주차: 발표와 후속 소통

- 팀장이 문제·해결책·시연·회고·제약과 공개할 변화 목록을 작성한다.
- 초안은 팀 내부, 게시 후에는 기수 전체가 본다. 팀 비공개 이력은 자동 공개하지 않는다.
- 관리자는 프로젝트를 원하는 순서로 선택하고 전체/전환/네트워킹 시간을 편성한다.
- 배포별 피드백을 받고 팀에서 예정/완료 상태와 답변을 남긴다.

## 대화·운영

전체·팀 대화에 답글, 멘션, 고정, 본인 수정, 읽음 처리가 있다. 대화를 아이디어·할 일·결정으로 연결할 수 있다. 알림은 본인에게만 제공한다.

참가자는 일반 Google 로그인만으로 가입한다. 초대 코드·이메일 사전 등록·메일 발송 서비스는 사용하지 않는다. 관리자 역할 변경은 마지막 관리자를 제거하지 못한다. 비활성화된 사용자도 운영자 목록에서 다시 활성화할 수 있다.

팀 자료는 관리자에게 자동 공개되지 않는다. 팀장이 운영자에게 기간과 편집 여부를 지정한 지원 권한을 줄 수 있다. 종료 기수는 읽기 전용이며 운영 설정, 신고·정정 등 관리상 필요한 예외만 허용한다.

## 파일과 AI 설정

첨부는 PNG/JPEG/WebP/PDF/TXT/MD, 최대 10MiB다. Firebase Storage의 vibecoding2/private/<cohort>/ 아래 저장한다. 요청 시 멤버십과 범위를 검사하며 영구 공개 토큰은 만들지 않는다. 내려받기 링크는 60초 유효하다. 이미지 캐릭터만 의도적으로 공개된 Firebase 자산이다.

AI 어댑터는 기본 비활성이다. Vercel **서버 환경변수**로 아래를 모두 설정해야 한다.

- AI_PROVIDER=openai
- AI_MODEL=계정에서 사용 가능한 Structured Outputs 지원 모델 ID
- OPENAI_API_KEY=운영자가 관리하는 키

실제 키를 문서·Git·채팅에 넣지 않는다. API 호출은 동의한 원문 작성자가 요청할 때만 발생한다. 1인 하루 10회, 원문 3만 자, 출력 6,000토큰으로 제한한다. 원문 정리와 팀 기획 초안은 먼저 검토 대기 자료로 저장한다. 원문/목표 문서가 변경되면 승인 충돌을 알린다. 실제 공급자 호출은 운영 키를 연결한 뒤 확인해야 한다.

공식 구현 참고: [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses), [Cloud Storage 서명 업로드](https://docs.cloud.google.com/storage/docs/samples/storage-generate-upload-signed-url-v4).

## 운영상 구분

- 채팅·자료는 20초 주기 갱신이다. 실시간 공동 편집은 제공하지 않는다.
- 이전 대화·아이디어·댓글·이력은 더 불러오기로 탐색한다.
- 보관 기간은 정책 값이다. 자동 일괄 삭제는 실행하지 않는다.
- 녹취록 텍스트를 받으며 녹음/음성 인식 서비스는 별도 연동 대상이다.
- preview의 참가자는 가상 인물이다. 역할 전환, 파일, 모든 변경은 브라우저 메모리에서만 유지된다.
- 이번 릴리스는 GitHub main의 자동 배포와 Vercel CLI 배포 모두 정상 완료됐다.

개발 검증: npm test, npm run test:e2e. 실제 Firebase 통합 검증은 로컬 개발 서버와 .env.local이 준비된 상태에서 npm run test:integration으로 실행한다. 스크립트는 test-workshop-* 격리 기수와 해당 파일만 만들고 정리한다.

세부 입력 기준과 상태 전환은 [생각 구체화·문제정의](problem-definition.md)를 참조한다.
