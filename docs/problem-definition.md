# 생각을 문제정의로 다듬는 흐름

기준일: 2026-10-17. 대시보드 1단계와 아이디어 상세에서 사용한다.

## 참가자가 하는 일

1. 대시보드 상단 **프로젝트 시작 입력**에서 처음 생각의 제목과 경험을 남긴다. 처음 생각 / 경험 구체화 / 문제정의 초안의 입력 순서가 보인다.
2. **카드 올리기**를 누르면 같은 시작 화면에서 다섯 질문 입력으로 바로 넘어간다. 일부만 임시 저장할 수 있다. 기존 내용은 **작성 중인 생각 이어쓰기**로 선택한다.
3. 다섯 질문을 채우고 **저장하고 문제정의로**를 누른다. 모르는 답은 `확인 필요`라고 적는다.
4. 문제의 영향, 해결 후 변화, 문제정의 문장, 통제범위를 작성한다. **초안 저장**은 미완성 상태에서도 가능하다.
5. 동료의 댓글·질문을 확인하고 변경 이유와 함께 새 초안을 저장한다. 초안 번호는 1, 2, 3…으로 이어진다.
6. 모든 필드와 문장 점검을 마친 뒤 **선정 준비 완료**를 누른다. 투표·개인 프로젝트의 출발점으로 쓰려면 기수 전체에 공유한다.

## 다섯 질문

- 누가 겪나요?
- 언제, 어디서 일어나나요?
- 그 순간 무엇을 하려다 막히나요?
- 지금은 어떻게 해결하고 있나요?
- 얼마나 자주 일어나나요?

현재 해결 방법에는 실제 사용하는 앱 이름을 적어도 된다. 확인되지 않은 사실을 대신 생성하지 않는다.

## 문제정의카드

- 왜 그게 문제인가: 불편, 손실, 어려움.
- 해결되면 무엇이 달라지나: 사람의 행동과 경험의 변화.
- 문제정의 문장: 누가 / 어떤 상황에서 / 무엇 때문에 / 어떤 어려움을 겪는지 네 입력을 하나의 문장으로 표시한다.
- 통제범위: 직접 바꿀 수 있는 부분 / 협조가 필요하거나 바꾸기 어려운 부분 / 이번 4주에서 다룰 범위.
- 문장 점검: 앱 이름이나 만들 기능으로 해결책을 미리 정하지 않았는지 본인이 확인한다.

앱·기능 표현 감지는 안내용 단어 검사다. 의미를 이해하는 AI 판정이 아니며 임의의 모든 앱 이름을 알아내지 않는다. 경고가 있어도 초안 저장은 가능하다. 확정은 사람이 문장을 점검한 후 한다. 질문 및 문제정의의 일반 텍스트는 각 700자, 변경 이유는 120자까지 받는다.

## 상태와 수정

생각 남김 → 구체화 중 → 문제정의 중 → 선정 준비. 상태는 저장한 내용으로 계산한다. 저장 전 입력은 초안 번호나 보드 상태에 반영하지 않는다.

질문을 다시 저장하거나 최초 생각을 수정하면 선정 준비와 문장 점검을 해제한다. 문제정의를 다시 검토·확정해야 한다. 질문 저장은 문제정의 초안 번호를 증가시키지 않으며, 문제정의 저장은 새로운 번호를 만든다. 변경 전 내용은 이력에 보존한다.

작성자만 공유 중인 카드를 수정할 수 있다. 후보·선정·종료 원본은 수정하지 않는다. 다른 사용자는 공개 범위에 따라 읽고 의견을 남긴다. 공개 범위를 바꾸면 그 카드의 과거 이력과 댓글도 같은 범위에 보인다. 종료 기수는 읽기 전용이다.

## 선정과 기획 연결

새 투표 후보와 새 개인/직접 선정 프로젝트는 선정 준비를 마친 전체 공유 카드로 제한한다. 후보에는 원본 revision과 질문·문제정의 전체 스냅샷을 고정한다. 출시 전에 이미 고정된 구형 투표는 기존 후보로 선정할 수 있도록 호환성을 유지한다.

프로젝트 설명에는 확정 문제정의 문장이 들어간다. 기획·개발의 `문제와 사용자` 문서가 아직 없으면 출발 아이디어, 질문 답변, 문제정의 초안과 통제범위를 초기 편집 내용으로 제시한다. 참가자가 저장한 뒤에는 자신의 문서로 관리한다. 기존 문서는 덮어쓰지 않는다.

## 저장과 검증

Idea.refinement에 answers, definition, ready, draft를 저장한다. refineIdea 명령은 revision과 작성자·상태·기수 권한을 검사하고 질문 저장 또는 문제정의 저장을 수행한다. Firestore 트랜잭션과 요청 식별자로 동시 수정 및 재전송을 처리한다.

모든 저장 사건의 snapshot에 당시 refinement를 포함한다. 원문 정정으로 파생 아이디어를 숨길 때에는 현재 질문·초안, 과거 스냅샷, 투표 후보의 refinement도 함께 비운다.


## 단계별 전시와 동료 피드백

대시보드의 **함께 보는 생각 보드**는 처음 생각 → 경험 구체화 → 문제정의 초안 → 선정 준비의 네 열로 전시한다. 작성한 다섯 질문과 답변, 문제정의 문장·영향·변화·통제범위를 카드에서 직접 읽을 수 있다. 긴 내용은 **내용 펼치기**로 확인한다.

- **전체 단계**는 네 열의 흐름을 함께 보여준다. 단계 이름을 누르면 해당 단계의 카드만 모아 본다. 모바일에서는 열을 옆으로 밀거나 한 단계를 선택한다.
- **아이디어 흐름** 또는 **이 흐름만 보기**로 한 아이디어의 발전 과정을 모아 본다. 검색은 생각·질문 답변·문제정의 내용을 대상으로 한다.
- 각 카드의 **피드백**을 열고 **이 내용에 피드백**을 작성한다. 피드백은 해당 단계와 저장 버전에 연결되므로 이후 초안을 수정해도 당시 내용에 남는다.
- **최신 카드 다듬기**는 작성자의 최신 편집 화면을 연다. 과거 초안을 직접 덮어쓰지 않는다. 초안별 내용과 바꾼 이유를 나란히 비교할 수 있다.
- **이 아이디어의 이전 버전 더 보기**, **이전 피드백 더 불러오기**로 처음 조회한 범위 이전 기록을 추가한다. 댓글 수는 현재 불러온 댓글 기준이다.

기존 댓글은 `아이디어 전체에 남긴 의견`으로 보존한다. 전체 변화 이력의 댓글 목록에도 새 피드백의 단계·버전을 표시한다. 나만 보기·팀 공유·전체 공유의 기존 조회 권한을 그대로 적용한다. 종료된 아이디어와 기수는 피드백을 추가할 수 없다.

저장 형식은 Comment.context의 stage(thought/questions/definition/ready)와 revision이다. 서버는 해당 아이디어의 실제 저장 이력을 조회하고, 그 버전에 해당 단계가 작성되어 있는지 확인한다. 없는 버전이나 작성 전 단계에 대한 피드백은 거절한다. 동일 내용이 이후 저장 사건에 복사되면 최초 전시 버전을 사용하며, 이미 피드백이 붙은 다른 버전은 별도로 유지한다.


## 시작 입력과 전시의 연결

시작 화면은 참가자가 기록을 만드는 곳이고, 아래 전시 보드는 저장한 내용과 동료 의견을 함께 보는 곳이다. 처음 생각을 저장한 결과의 ID를 받아 그 카드의 질문 입력을 즉시 연다. 다섯 질문을 저장하면 같은 자리에서 문제정의 초안으로 이어진다. 처음 생각만 있는 상태에서는 문제정의로 건너뛸 수 없다.

상단의 **생각 남기기**는 대시보드에서 시작 입력으로 이동한다. 다른 주차를 보고 있어도 1단계로 돌아온다. **새 생각 시작**은 별도 카드를 작성하고, **작성 중인 생각 이어쓰기**는 본인의 수정 가능한 기존 카드를 연다. 나만 보기·팀·전체 공개 범위와 저장 이력, 변경 이유를 동일하게 적용한다.
