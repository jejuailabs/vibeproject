# 구현 순서와 작업 범위

기간은 개발 인력과 실제 환경에 따라 정한다. 워크숍의 4주 일정과 플랫폼 자체 개발 기간을 혼동하지 않는다.
한 단계가 끝나면 실제 사용 흐름을 확인하고 다음 단계로 진행한다.

## M0. 기반

- 저장소/런타임/환경 예시/문서 연결.
- Auth, Google 자동 가입, 역할 모델, 기본 거부 Rules.
- 개인/전체/프로젝트 공통 레이아웃과 반응형 이동.
- 에뮬레이터와 가상 계정/기수 시드.

완료: 가입 가능한 계정과 미가입 계정이 구분되고 다른 기수 데이터가 차단된다.
운영용 키가 없어도 개발 환경 실행 경로가 있다.

## M1. 첫 생각에서 공동 보드까지

- 활동 생성/개방/마감과 제출.
- 개인 초안, 피드 게시, 아이디어 생성, 전체 보드.
- 댓글/질문/반응.
- 첫 공유 버전과 직접 링크.

완료: 참가자가 휴대폰으로 활동에 들어와 작성한 생각이 기수 보드에 나타나고 동료가 의견을 남긴다. 개인 초안은 다른 사람에게 보이지 않는다.

## M2. 플랫폼 내부 소통

- 전체 채널과 프로젝트 채널 기반.
- 메시지/답글/멘션/고정 공지/읽지 않은 구간.
- 피드와 채팅의 대상 연결, 대화 수동 정리.
- 앱 내부 알림.

완료: 메시지를 선택해 생각/결정 초안/할 일로 연결하고 근거를 확인한다.
아직 팀이 없는 참가자는 전체 채팅만 사용한다.
임시 프로젝트 fixture로 팀 권한을 검증하고 M3에서 실제 생성 흐름과 연결한다.

## M3. 투표와 프로젝트 구성

- 후보 버전 고정, 투표 제출/변경/마감/집계.
- 최종 선정과 미선정 종료.
- 프로젝트 생성, 신청/승인, solo/team.
- 팀장·관리자 캐릭터 목록과 프로젝트 디렉터리.

완료: 동시 승인에서도 정원/1인 활성 프로젝트 제한이 유지되고 선정 재시도가 프로젝트를 중복 생성하지 않는다.

## M4. 기획과 성장 이력

- 문제/기능/화면/디자인/데이터·권한 문서.
- 초안 revision, 확정 버전, 베이스라인.
- 결정과 주요 변화 타임라인.
- Markdown/ZIP 내보내기.

완료: 첫 카드부터 프로젝트의 기획 변경과 내보낸 문서 버전까지 추적한다.
이전 내보내기는 이후 수정에 따라 변하지 않는다.

## M5. 개발·현장 운영 완결

- 개인/프로젝트 준비 체크리스트.
- 작업/도움 요청/배포/피드백.
- 발표 일정·데모·회고·공개 성장 이력.
- 운영자 진척/지원 화면.

완료: AI 없이도 가상 4주 과정을 시작부터 발표 종료까지 수행한다.
이 단계까지 권한/오류/모바일 검증을 마쳐야 Workshop-ready다.

## M6. AI 보조

- 공급자 어댑터/사용량/기능 플래그.
- 녹취록 정리와 근거 기반 제안.
- 검토/부분 승인/충돌/재시도.
- 대화 기반 기획 초안.

완료: 검토 전 데이터가 바뀌지 않고, 원본 변경/중복 재시도/공급자 실패가 안전하게 처리된다.
공급자가 정해지면 M4~M5와 병행 가능하다. 핵심 수동 흐름을 AI 설정 때문에 막지 않는다.

## 우선순위 판단

P0: 데이터 손실/권한 누출/투표 부정합/이력 단절/핵심 흐름 차단.
P1: 운영 효율과 사용성, 검색 범위, 피드백 관리.
P2: 고급 아바타 애니메이션, 전문 검색, 외부 알림, 실시간 공동 편집.
P2를 위해 P0/P1 검증을 생략하지 않는다.

## 단계별 공통 완료 체크

- 현재 권한에 맞는 실제 데이터 조회/수정.
- 빈 상태/로딩/실패/재시도/권한 거부.
- 접근 가능한 모바일 화면.
- 해당 유스케이스의 의미 있는 검증.
- 문서와 구현 차이 반영.
- mock/미완료/외부 설정 필요를 명시.

## 첫 개발 작업의 구체적 산출물

기수 참가자 로그인, 현재 활동, 내 생각 입력, 공개 확인, 아이디어 카드, 공동 보드, 댓글까지의 실행 가능한 수직 흐름.
인증 없이 모든 버튼이 열리는 데모를 최종 구현으로 처리하지 않는다.
