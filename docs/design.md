## 확인한 레퍼런스

사용자가 지정한 디자인을 제품 전체의 주 기준으로 사용한다. 이미지와 관련 작업을 실제 브라우저에서 열어 비교했다. 이전의 “원본 이미지를 확인하지 못했다”는 설명과 어두운 Arena 토큰은 이번 정의로 대체한다.

- [NBA Player Profile — Stats Dashboard UI / Nixtio](https://dribbble.com/shots/27056095-NBA-Player-Profile-Stats-Dashboard-UI): 선명한 보라·핑크·블루의 연속된 배경, 왼쪽 큰 인물, 중앙 기록 그래픽, 오른쪽 이름·통계, 하단 데이터 목록. 제품의 주 시각 기준.
- [Football Club Management Platform / Nixtio](https://dribbble.com/shots/26553628-Football-Club-Management-Platform): 좁은 공통 탐색, 명단과 선택된 상세 영역, 문맥에 따른 탭·입력 그룹의 위계.
- [Football Manager Dashboard / Nixtio](https://dribbble.com/shots/24895132-Football-Manager-Dashboard): 압축된 운영 지표, 사람과 기록을 함께 보여주는 목록·표, 일관된 선택 상태.
- [AI Productivity & Task Management Dashboard UI / Nixtio](https://dribbble.com/shots/26475284-AI-Productivity-Task-Management-Dashboard-UI): 작업 영역과 대화 도크의 공존, 담당자·상태·다음 행동을 가까이 배치.
- [Task Management Dashboard / Nixtio](https://dribbble.com/shots/19864229-Task-Management-Dashboard): 역할이 다른 영역을 분할하고 업무와 대화를 연결하는 구성.

뒤의 네 작업은 같은 NBA 제품의 하위 페이지가 아닌 동일 디자이너의 별도 작업이다. 목록·상세·업무의 구성 원리를 참고한다. 서로 다른 작업의 색상을 섞지 않고 NBA 레퍼런스의 시각 언어로 통일한다. 사진·스포츠 로고·레퍼런스 이미지는 앱 에셋으로 복제하지 않는다.

## 공통 원칙

메인 한 화면만 장식하지 않는다. 로그인, 개인·팀·전체 대시보드, 아이디어, 프로젝트, 이력, 현장 활동, 투표, 기획·개발, 자료실, 대화, 발표, 알림, 운영에서 같은 탐색과 선택·편집·빈 상태 규칙을 유지한다.

일반적인 검은 배경과 독립적인 보라색 상자를 반복하지 않는다. 연속된 색면 위에 인물과 정보가 놓이고, 본문은 반투명 표면, 실제 입력·문서 편집은 차분한 짙은 표면으로 구분한다. 화면 목적에 따라 보드·명단·편집기·표·대화로 구성을 달리한다.

인물은 장식용 별도 그림이 아니라 사용자가 선택한 캐릭터다. 개인은 본인, 프로젝트는 소속 구성원, 전체는 활동 중인 구성원을 보여준다. 능력치·승률·가짜 통계는 만들지 않는다. 숫자는 현재 권한으로 불러온 아이디어·의견·이력·문서 수를 사용한다. 중앙 그래픽은 현재 주차와 4단계 이동을 나타내며, 완료율을 뜻하지 않는다.

## 이미지와 접근성

16개 기존 AI 캐릭터의 원본·WebP·썸네일은 Firebase Storage에만 둔다. Vercel과 GitHub에는 앱 코드·캐릭터 ID·공개 URL 목록만 배포한다. 이번 변경에서 새 이미지 업로드나 저장소 이동은 하지 않았다.

폼 label·버전 충돌 보호·키보드 조작·모달을 유지한다. 메뉴에는 접근 가능한 이름, 현재 문서와 기능 탭에는 현재 선택 표시를 넣는다. 카드의 실제 텍스트는 이미지에 합성하지 않는다. 모션 감소 환경에서는 이동 효과를 끈다.

## 2026-10-13 참가자가 바로 시작하는 활동 보드

대시보드의 첫 목적은 참가자가 지금 무엇을 남겨야 하는지 보여주는 것이다. `journey.css`를 court.css 다음에 로드한다. 기존 보라·핑크·블루 색면, Firebase 캐릭터와 대화창을 유지하고 콘텐츠 순서를 바꾼다.

- 상단 4단계: 생각 꺼내기 / 함께할 문제 고르기 / 만들고 고치기 / 결과 나누기. 기수의 현재 주차로 시작하며 다른 단계도 살펴볼 수 있다. 탐색만으로 운영 단계는 변경하지 않는다.
- 각 단계에 질문, 이번에 남길 결과물, 입력 또는 행동 버튼을 함께 보여준다. 기록 여부는 실제 카드·프로젝트·기획 기준·배포·발표 데이터로 표시한다.
- 1단계: 모달 없이 제목·경험 두 칸에 작성한다. 전체 공유가 기본이며 나만 보기, 프로젝트 공간의 팀 공유를 지원한다. 아래 색상 카드 보드에서 바로 동료의 생각을 읽는다.
- 카드 클릭: 기존 댓글·본인 수정·이전 내용 및 변경 이유를 이어 쓴다. 종료된 카드는 보관 상태로 구분한다. 조회 권한을 적용해 다른 사람의 비공개 카드를 표시하지 않는다.
- 2단계: 투표와 개인/팀 프로젝트 선택, 현재 프로젝트 카드. 프로젝트가 없으면 다음 행동을 설명한다.
- 3단계: 7개 문서를 구체적인 질문 카드로 보여주고 선택한 문서 편집기로 이동한다. 개발 환경, 기획 버전 확정, 배포 기록은 해당 작성 위치로 이동한다.
- 4단계: 발표·변화 과정·회고와 동료 피드백. 팀장과 팀원의 실제 권한에 맞는 버튼을 표시한다.
- 활동 보드 하단에서 현장 질문, 자료·녹취록, 대화·진행 공유에 접근한다. 기능 화면에는 활동 보드로 돌아오는 버튼을 둔다.
- 인물 프로필·통계·메이커 명단은 활동 보드 아래에 둔다. 모바일은 단일 열 입력과 카드, 2열 단계 탐색을 사용한다.
