# 디자인 정의

## 참고와 확인 범위

사용자 제공: [NBA Player Profile — Stats Dashboard UI / Nixtio](https://dribbble.com/shots/27056095-NBA-Player-Profile-Stats-Dashboard-UI).
페이지 설명의 프로필·통계·기록 중심 콘셉트는 확인했다. 원본 이미지의 세부 배치는 도구 오류로 확인하지 못했다.
아래 토큰과 배치는 원본을 측정한 값이 아닌 VibeCoding2용 제안이다. 구현 시 참고 이미지를 확인하되 선수 사진·브랜드·에셋을 그대로 복제하지 않는다.

## 방향

캐릭터와 프로필이 중심인 활동 공간. 개인은 자신, 팀장은 파티, 운영자는 전체 팀을 조망한다.
업무 문서와 긴 대화는 편안하게 읽을 수 있어야 한다. 장식 때문에 정보 밀도나 명도 대비를 희생하지 않는다.
랭킹·전투력 대신 현재 단계, 완료한 준비, 도움 요청, 주요 성취를 표현한다.

## 레이아웃

- 1440px 안팎 데스크톱: 왼쪽 224px, 중앙 유연, 오른쪽 채팅 320~360px, 간격 24px.
- 1280px 미만: 채팅 기본 접힘. 필요 시 drawer로 연다.
- 1024px 미만: 탐색 메뉴 축소, 메인 한 열.
- 600px 이하: 상단 메뉴 버튼과 공간 탭, 별도 채팅 화면.
- 본문 읽기 폭은 약 680~820px, 보드/캐릭터 목록은 가용 폭 사용.
- 캐릭터 카드는 스크린 크기에 따라 1~4열. 중요한 정보가 가로 스크롤에만 갇히지 않게 한다.

## 주요 컴포넌트

ProfileHero: 아바타, 이름, 역할, 현재 단계, 다음 행동.
MemberCard: 아바타, 이름, 담당, 공개 작업 상태, 도움 요청 표시.
ProjectCard: 목표, 단계, 팀원 일부, 최신 데모.
FeedComposer: 유형, 본문, 범위, 첨부, 게시.

ReadinessChecklist: 완료/미완료/해당 없음/예외, 담당자와 확인 시각.

## 아바타

16종 AI 생성 캐릭터를 기본 라이브러리로 제공한다. 내 공간의 캐릭터 변경 버튼에서 선택/미리보기/저장한다. 이미지 원본과 WebP/썸네일은 Firebase Storage에만 호스팅하며 Vercel은 앱 코드와 URL 목록을 배포한다.
사진 사용을 강제하지 않는다. 게임 캐릭터는 표현 방식이며 능력치 판단이 아니다.
선택 ID는 본인 members/profiles 문서에 트랜잭션으로 저장되며 프로필·팀 카드·채팅에서 같은 ID를 사용한다. 여러 참가자가 같은 캐릭터를 선택할 수 있다. 사용자 이미지 업로드는 후속 범위다.

## 접근성/입력

키보드로 메뉴, 피드, 투표, 채팅에 접근 가능해야 한다.
포커스가 drawer/dialog에 들어간 뒤 닫으면 원래 위치로 돌아온다.
폼 label과 오류 설명을 연결한다. 애니메이션 감소 설정을 지원한다.
클릭 영역은 대략 44px 이상을 목표로 한다.
채팅 새 메시지는 스크린리더 알림을 제한하여 읽기를 방해하지 않는다.
스크롤을 올려 과거 메시지를 보는 중에는 강제로 맨 아래로 이동하지 않는다.
카드 나열은 접근 가능한 DOM 순서를 유지한다.

## 시각 검증

개인/리더/운영자, 빈 데이터/긴 제목/많은 팀원/종료 카드/오류, 1440·1024·390px를 확인한다.
실제 한국어 콘텐츠로 줄바꿈과 버튼 잘림을 확인한다.

## 2026-10-12 Arena 개편

- 어두운 보라색 캔버스, 강한 보라/코랄 조명, 라임색 주요 행동 버튼.
- 개인 대형 캐릭터 프로필, 전체 공간의 그룹 비주얼, 4주 진행 표시와 실제 활동 수치.
- 게임 라인업 방식의 참가자 카드. 클릭하면 해당 참가자의 열람 가능한 생각만 필터링한다.
- 캐릭터 선택은 데스크톱 4×4 그리드와 대형 미리보기, 모바일 세로 스크롤로 제공한다.
- 역할/권한/능력치를 캐릭터 선택과 연결하지 않는다.
- 에셋 저장 경로 및 전체 프롬프트는 [image-assets.md](image-assets.md)에 기록한다.
