# 활동과 단계 전환

## 상태를 분리하는 이유

기수의 주차, 활동의 개폐, 아이디어 선정, 프로젝트 진척은 서로 다르다. 한 활동을 연다고 모든 프로젝트 상태를 변경하지 않는다. 활동별 activityId를 사용하고 동시에 열린 활동 중 하나를 featuredActivityId로 강조한다.

## 기수와 활동 상태

기수: draft → recruiting → running → completed → archived.
활동: draft → open → closed → archived.

활동 개방 조건: 질문/안내, 대상, 제출 양식, 공개 정책, 담당자.
종료 후 제출은 잠기며 운영자가 이유를 기록하고 재개할 수 있다. 재개 시 기존 제출은 유지하고 수정 제출 버전을 추가한다. QR은 인증을 생략하지 않고 로그인 후 원래 활동으로 돌아오게 한다.

## 아이디어 상태

draft → shared → candidate → selected 또는 closed_unselected.

- draft: 소유자만 열람. 최소 제목 또는 문제 내용이 있어야 저장.
- shared: 작성자가 공개 범위와 내용을 확인. 기수 내 문제 보드에 게시.
- candidate: 투표 후보 확정 버전을 고정. 문제 대상·상황·불편이 필수.
- selected: 운영자가 선정 이유와 출발 버전을 확정.
- closed_unselected: 선정 라운드에 참여했으나 채택되지 않음. 당시 내용/표수/토론 보존.
- 선정 대상이 아니었던 초안과 일반 공유 카드를 일괄 종료하지 않는다.

candidate 이후 원문 수정은 잠긴다. 공유 단계로 되돌릴 때 이유와 새 라운드를 기록한다. 종료 카드는 기본적으로 읽기 전용이며 재개 후에만 수정한다. 재개는 shared로 이동하는 사건이고 이전 종료를 지우지 않는다.

## 프로젝트 상태

forming → planning → ready → developing → reviewing → completed → archived.

| 전환 | 필수 조건 | 확정자 | 보존할 기록 |
|---|---|---|---|
| 선정 → forming | 출발 아이디어 버전, 프로젝트명, solo/team | 기수 관리자 | 선정 결정, 연결 원본 |
| forming → planning | 구성원과 리더 확정, 참여 동의 | 리더/기수 관리자 | 구성원 목록 시점 |
| planning → ready | 문제/사용자, 구현 범위, 핵심 흐름, 화면/권한, 완료 기준 | 리더, solo는 본인 | 기획 베이스라인 |
| ready → developing | 개인/프로젝트 필수 준비 완료 또는 예외 기록 | 리더 | 준비 상태, 개발 시작 버전 |
| developing → reviewing | 데모 링크, 핵심 흐름 점검, 알려진 문제 | 리더 | 릴리스와 문서 버전 |
| reviewing → developing | 반영할 수정 항목 | 리더 | 수정 사유 |
| reviewing → completed | 발표 결과, 최종 데모/제약, 회고, 공개 요약 | 리더 | 최종 스냅샷 |
| completed → archived | 기수 종료 정책 적용 | 기수 관리자 | 보관 사건 |

실제 작업은 planning 중에도 가능하다. 상태는 공식 기준점이며 비밀 키/권한 같은 보안 필수 조건을 우회하는 수단으로 사용하지 않는다.

## 단계 예외

권한 있는 담당자가 이전 단계로 돌리거나 준비 항목을 예외 처리할 수 있다. reason, actorId, at, affectedRequirements가 필수다. 변경 전후 상태와 기준 버전은 보존한다. UI에서 예외 사실과 미완료 항목을 표시한다.

## 투표 규칙

1. 진행 방식(개인/팀/혼합)을 결정한다.
2. 후보와 각 candidateVersionId를 고정한다.
3. 라운드를 연다. 표는 한 후보에 최대 1표, 전체 min(설정 표 수, 후보 수).
4. 마감 전 본인 표를 교체할 수 있다.
5. 서버 시각 기준 마감 후 제출을 거절한다.
6. 마감 후 집계 결과를 공개하고 최종 선정은 운영자가 별도로 확정한다.
7. 동점은 자동 탈락시키지 않는다. 토론·재투표·운영자 결정과 이유를 남긴다.
8. 미선정 후보를 종료 처리한다. 프로젝트 참여 선택을 별도로 진행한다.

비밀투표 기본: 본인은 자신의 투표를 확인하며 다른 구성원과 운영자 UI에는 개인별 표를 노출하지 않는다. 서버는 중복 방지를 위해 투표자 식별자를 저장하므로 완전한 익명성이라고 표현하지 않는다.

## 팀 구성

joinRequest 상태: pending/accepted/rejected/withdrawn.
리더 또는 기수 관리자가 구성원을 확정한다. 기본적으로 기수당 1개 활성 프로젝트에 참여한다. 동시 신청/승인 시 서버에서 이 제한을 재확인한다.
정원 초과 시 승인하지 않고 대기 상태를 안내한다. 팀 탈퇴·이동은 기록하며 마지막 리더는 이관 없이 탈퇴할 수 없다.
프로젝트 생성 재시도는 동일 선정 결정에서 중복 프로젝트를 만들지 않는다.

## 병합·분리·종료

여러 아이디어를 한 프로젝트로 연결할 수 있다. 모든 원본과 출발 버전을 연결하며 아이디어 원본은 합쳐 덮어쓰지 않는다.
프로젝트 분리는 새 프로젝트를 만들고 derived_from 관계를 남긴다.
선정된 카드의 프로젝트 연결을 조용히 해제하지 않는다. 취소·재선정은 별도 이유와 사건으로 처리한다.
완료는 구현 범위의 종료이고 미선정 종료는 실행 후보에서 제외된 상태다. UI에서 두 상태를 같은 '완료'로 표시하지 않는다.
