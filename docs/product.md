# 제품 정의와 범위

## 제품 목표

워크숍에서 나온 생각과 결과가 여러 도구에 흩어지지 않도록 한다. 오프라인 대화의 결과를 참가자가 직접 정리하고, 팀 안에서 논의하며, 처음 생각이 구현 결과로 변하는 과정을 남긴다.

## 사용자

| 사용자 | 목적 |
|---|---|
| 참가자 | 생각 작성, 활동 참여, 다른 사람과 토론, 개인/팀 개발 |
| 프로젝트 리더 | 팀 구성 확정 후 역할 조율, 기획 확정, 진행 관리 |
| 퍼실리테이터 | 활동 운영, 질문과 정리 지원, 막힌 지점 발견 |
| 기수 관리자 | 구성원·일정·투표·선정·운영 정책 관리 |
| 플랫폼 관리자 | 기수 생성, 서비스 운영 및 제한된 지원 |

팀장은 기수 관리자와 다른 역할이다. 관리자는 참가자의 비공개 메모나 모든 팀 대화를 자동 열람하지 않는다.

## 핵심 개념

- 기수: 한 번의 4주 과정. 여러 기수를 저장할 수 있으나 첫 UI는 현재 기수 중심이다.
- 활동: 주차 안에서 열고 마감하는 질문/제출/투표/점검 단위.
- 피드 글: 생각·질문·진행 공유·활동 정리를 가볍게 게시하는 단위.
- 아이디어: 대상·문제·상황·해결 가설을 정리한 카드.
- 프로젝트: 선정된 아이디어를 구현하는 공간. solo/team 구분을 가진다.
- 확정 버전: 공유나 결정 시점의 내용을 보존한 스냅샷.
- 사건: 선정, 구성원 변경, 문서 확정, 배포 같은 발생 기록.
- 결정: 제안과 구분되는 담당자의 명시적 확정.
- 공개: 기본적으로 기수 구성원 대상. 인터넷 공개와 다르다.

## 전체 제공 범위

1. Google 로그인, 참가자 자동 가입, 프로필·아바타.
2. 개인/프로젝트/전체 대시보드와 맥락별 메뉴.
3. 활동 안내, 제출, 진행 화면, QR/직접 링크.
4. 개인 피드, 기수/팀 피드, 패들렛 형태 카드 보드.
5. 댓글·답글·반응·멘션, 전체 및 프로젝트 채팅.
6. 투표와 선정, 미선정 종료, 참여 신청과 팀 확정.
7. 문제/기능/화면/디자인/데이터·권한 기획.
8. 녹취록 텍스트 기반 AI 초안과 사람 검토.
9. 기획 버전 기반 Markdown 묶음 내보내기.
10. 개인 설치 준비·프로젝트 서비스 준비 체크리스트.
11. 할 일, 데모, 피드백, 주요 변경 타임라인.
12. 발표 일정, 전시, 질문, 회고.

## 이번 범위에서 제외

실시간 음성 녹음/전사, 외부 메신저 수집, 1:1 DM, 영상회의, 웹 내 코딩 IDE, 에이전트 자동 코드 실행, 자동 GitHub/Firebase 프로젝트 생성, 자동 배포, 결제/수료증, 참가자 순위 경쟁, 외부 공개 소셜 네트워크, 복잡한 간트/스프린트 관리.

추후 확장은 가능하지만 핵심 범위를 지연시키지 않는다. 플랫폼 알림은 앱 내부부터 시작한다.

## 성과를 판단하는 기준

- 참가자가 현재 활동과 다음 행동을 알아볼 수 있는가.
- 공개된 첫 생각에서 최종 프로젝트까지 추적 가능한가.
- 대화를 수동 재입력하지 않고 결정/기획으로 연결할 수 있는가.
- 미선정 아이디어도 원본과 종료 이유가 남는가.
- 운영자가 준비 지연과 도움 요청을 확인할 수 있는가.
- 실제 현장에서 모바일로 입력하고 투표할 수 있는가.

참가자를 게시물 수나 접속 시간으로 평가하지 않는다. 운영 지표는 제출/준비/도움 요청/프로젝트 단계 중심으로 집계한다.

## 범위 수준

- Core: 인증, 활동, 피드/카드, 채팅, 투표, 프로젝트, 이력.
- Workshop-ready: 기획/내보내기, 준비 체크리스트, 데모/발표, 운영·권한 검증.
- AI-assisted: 공급자 확정 후 녹취록 정리와 기획 초안. 없을 때 수동 경로 유지.

Core만 완성된 상태를 4주 운영 전체 완료라고 표시하지 않는다.
